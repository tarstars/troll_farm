* a command row's label decodes (`tf_full_decode_action`) and encodes back to the same index

## 3. `train_clone.py` — the trainer

* `SpatialActorCritic(plan_head=True)` from `cgauto/train_level1_ppo.py`; `PLAN_ACTION_SIZE` is
  imported, and a self-test walks this file's AST to prove no vocabulary size is written down here.
* Planes are built at load time by `tf_full_obs_from_state` through `nn_runtime.PlaneBuilder` — a
  thin batcher around the C ABI. `build_planes.py` stays the independent Python builder that
  proved, on 1,000 states, that the two agree.
* Two masked cross-entropies: a plan row trains the plan head under the 400-entry plan mask, a
  troll row the per-cell head under the 3,146-entry spatial mask. A row trains exactly one head,
  and that is a test, not a claim (below).
* Held out **by game** (the shard's deterministic `split`).
* Per-verb accuracy is reported and gates nothing (`docs/CONSTRAINTS.md`: fit statistics
  anti-predict transfer here; the bench judges).
* The checkpoint is the four-key format PPO reads — `model`, `optimizer`, `config`,
  `global_step` — with `plan_vocab_version` in the config.

```text
python3 local_claude_1/nn-bot/train_clone.py --self-test \
    --shard local_claude_1/nn-bot/results/pilot --name pilot
ok   the plan size comes from the network's own module, nothing is hard-coded
ok   the compiled runtime's plan vocabulary is this one
ok   the staged prefix is the turn's earlier trolls in ascending id order
ok   a plan row trains the plan head and a troll row the per-cell head, not both
ok   a label outside the mask raises rather than being trained on
ok   the four-key checkpoint loads into train_ppo_full.load_policy, a foreign one is refused
self-test: PASS (0 failures)
```

The last one saves a checkpoint, loads it back through `train_ppo_full.load_policy`, compares every
tensor, then rewrites the config's vocabulary to `v144-2026-08-28` and requires the loader to
refuse it.

### The cost of a plane, measured

`tf_full_obs_from_state` takes **15.1 ms a row** on this VM (66 rows/s in one process; the JSON
serialisation is 0.04 ms of that, so the cost is inside Rust). The arithmetic the coordinator needs
before training the real clone on the host:

* 817,811 rows ≈ **3.4 hours an epoch in one process**;
* the trainer takes `--workers`, and each worker builds its own library handle, so the host's 20
  threads bring an epoch to roughly **10–12 minutes** (the VM ran 2 workers at 55–58 rows/s).

Storing the planes instead is the trade the card already refused: 25 kB a row is ~20 GB.

## 4. The bench, amended (1–4)

```text
python3 local_claude_1/nn-bot/bench.py --self-test
ok   seat 0's rendering is the referee's own text, unchanged
ok   seat 1's rendering is the seat-exchanged game read as player 0
ok   the runtime's codec rotates seat 1 and round-trips on both seats
ok   TRAIN is emitted only when the environment's own dry run succeeds
ok   the game ends by the referee's own has_stalled, with a reason
ok   a whole turn taken through the runtime's masks is accepted by the referee
self-test: PASS (0 failures)
```

* **(1) planes and masks from the runtime.** A tensor policy is shown, per mini-step, the
  observation and the mask `tf_full_obs_from_state` builds, with the turn's earlier trolls staged;
  its choice is decoded back to command text by `tf_full_decode_action`. There is no bench-side
  plane or mask code. The last self-test above plays a whole turn that way and requires the
  referee to accept every command the runtime's mask allowed.
* **(2) the plan is a target, the dry run emits.** `nn_runtime.plan_trains` is the one adapter:
  it clones the referee, prepends `TRAIN ms cc hp chop`, runs the whole turn and asks whether the
  seat gained a troll — which is `rust/src/rl_full.rs::train_succeeds` procedure for procedure, so
  the purchase is billed against the post-MOVE/post-PICK bank with the occupancy the turn really
  produces. The self-test shows both sides of that: a TRAIN into the shack the starter is standing
  on fails, and the same TRAIN with the same turn's MOVE off the shack succeeds.
* **(3) the referee ends the game.** `nn_runtime.stall_check` calls `sim.engine.has_stalled` — the
  project's port of `game::engine::has_stalled` — with the persistent counter fed back in, and each
  row records `turns` and `ended_reason`. This is not cosmetic: **21 of the 24 day-1 games end
  early** (`grace_expired`), which the fixed 300-turn loop had been playing out into an empty map.
* **(4) both seats.** `--both-seats` plays every map twice. The compiled bot always believes it is
  player 0 (the protocol has no seat field, `fuzz_panel.materialize`), so `nn_runtime.SeatRendering`
  gives it its own view: its inventory first, its units as player 0, its tent as the map's `0`. The
  test for it is an identity, not an assertion: seat 1's rendering of a game equals seat 0's
  rendering of the same game with the seats exchanged.

## The one finding the real training needs to know

**The smoke clone never buys a troll.** Its plan head's masked argmax is "train nothing" on every
turn of all eight games. That is not a bug in the head or in the dry run — it is the label
distribution: 1,992 of the pilot's 2,954 plan rows are "train nothing" (67 %), because the label is
the *next* purchase and most turns have none nearby, and greedy argmax over a 67 % class stays
there. The teachers themselves buy 1–3 trolls a game.

Three honest ways out, none of which I took (they are the coordinator's call, and the card says the
bench judges): sample the plan head instead of taking its argmax; weight the plan loss by class; or
leave the head as it is and let PPO's own plan target take over from the clone's initialisation —
which is what Phase 3 does anyway. What matters for the handoff is that the number is measured and
named rather than discovered later as "the clone does not train trolls".
