**On "no referee error/illegal command is reported."** I read all 375 lines of `sim/engine.py`.
It has **no exception or error-reporting path for illegal commands at all** — every action handler
(`apply_moves`, `apply_harvest`, `apply_plant`, `apply_chop`, `apply_pick`, `apply_train`,
`apply_drop`, `apply_mine`) is guarded by an `if` that silently no-ops an illegal command (insufficient
funds, an occupied/foreign cell, an unknown unit id, zero chop, no fruit left, etc.) rather than
raising or logging anything. So "no referee error is reported" is trivially true for any input,
including garbage. The meaningful stand-in I used instead: does the *intended* effect actually
happen on the claimed turn — a silently no-op'd command (e.g. a TRAIN issued a turn before funds
truly clear) would desync the observed `trains`/inventory/score from the schedule's own claims. None
did, across all 1492 checks.

## Verdict

Claim (a) reproduces exactly and completely: all 1492 kept schedule-variants across all 400
map-seats replay through the real `sim/engine.py`, referee-exact, third-troll TRAIN turn included,
via a replayer I wrote from scratch rather than trusting `replay.py`; the two map-seats flagged as
incomplete (`c8133082187414ff` s1, `b4a37d9ea678626e` s1) are genuinely flagged `done: false` for
the `same` variant only, correctly excluded from the n=292 count, with their other three variants
intact. Claim (b)'s numbers all reproduce exactly, partly from `report.py` as committed and partly
(the §3 verb-order table) from the same JSON directly since `report.py` doesn't print that table
itself — a tooling gap, not a numeric error. Claim (c)'s ablation table reproduces exactly from
`ablation.json` without rerunning the search, but the prose "mean gap of about 18" is wrong (the
true mean is 21.7; 18 is the median, mislabeled). Claim (d)'s raid-rate table reproduces exactly via
a full independent re-execution of `raid_rate.py` from raw inputs (it reads no cache), but the
"orchard 6's own trees" sentence (109 raided / 1,583 felled by itself) doesn't match the source data
either from my rerun or from the cached JSON's own records (actual: 114 raided, 1,587 self-involved).
My main doubt about the method itself, beyond these two prose slips: the whole page is an idle-opponent,
no-blocking model by design (stated up front, §1) and stage 1's own conclusion (§7) is that rules,
not the planner, should ship first — the verification above only confirms the *arithmetic and the
referee-fidelity* of what was measured, not whether an idle-opponent opening plan holds up against a
real opponent, which the page itself does not claim.
