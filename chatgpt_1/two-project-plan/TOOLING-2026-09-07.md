## 2. Four incompatibilities that affect a verdict

**Historical verdict is not current policy.** The main field script returns FIELD_ABOVE_ZERO or FIELD_BELOW_ZERO from strict-win confidence bounds. A tie contributes zero, rather than half a match point. N:panel_gate.py accepts own-score curves independently of opponents. Neither is the proposed prospective W+0.5D gate. A new aggregation version must be frozen and tested before its candidate results exist; leave historical outputs attached to their actual old rules.

**A seal is not a running experiment.** The existing seal emits 512 seed blocks, each assigned round-robin to one of five fixed external opponents, at player zero. Two arms cost 1,024 games, not 5,120. Opening consumes the bank even if execution later stops. It neither makes the endpoint deterministic nor guarantees that a later runner uses the source frozen in the gate.

**Failure rows must survive early rejection.** The neighbour saves request intent and raw responses, which is valuable, but validation can fail before a successful row is appended. Aggregating only rows would censor failures. The main endpoint driver is weaker still: no durable pre-POST journal and insufficient authenticated outcome/identity checks. Preserve each planned, attempted, failed, completed and ambiguous request in one ledger. An invalid deployment is evidence against deployment safety, not a row to drop silently.

**Correct uncertainty depends on the sampling unit.** Two seats and several opponents on the same map are correlated. Resample the entire map block together. The seed bank's one-opponent/player-zero blocks are a different design from a fully crossed two-seat panel. State exactly which population the interval addresses. Bootstrapping maps against fixed agents cannot estimate uncertainty over unseen opponent policies.

## 3. Minimal missing execution layer — a specification, not implemented here

A bounded runner should consume a frozen global experiment manifest with:

- source/export hashes and compiler certificate for both arms; main/neighbour/helper pins; authority record and total request cap;
- a hash of the seal receipt or open development bank; fixed opponent IDs, seat schedule, block IDs and prescribed randomized arm order;
- the exact outcome rule, deployment rules, aggregation version, interval method, stopping rule and successor-seal requirement.

Each global job has a unique key (experiment, block, arm, opponent, seat, repeat). Partition into immutable chunks of at most twelve jobs. Before the single POST, durably record INTENT, input/source hashes and the remaining budget. After a response, save its original bytes/hash, then its replay and normalized identity. Only then mark VALID, DEPLOYMENT_FAILURE, PROTOCOL_FAILURE or OTHER_CLASSIFIED_FAILURE. Network ambiguity leaves AMBIGUOUS, not UNSENT.

On restart, compare all manifest and source hashes, check the global budget and resume only demonstrably unattempted jobs. For AMBIGUOUS jobs, reconcile an existing result by its retained server identity or stop for adjudication. **Never blindly repeat a possibly accepted POST.** Fetching an already identified replay is not a new play request; distinguish the two operations. An idempotency claim requires a supported platform guarantee, not a locally generated key the endpoint never reads.

One receipt joins all chunk hashes, exact game IDs, source snapshots, seed echoes, normalized initial-state hashes, requested/actual opponents, seats, official outcomes and failures. The control and candidate must share the declared initial block. Source changes, substituted opponents, silently repeated seeds, stale-baseline modules, missing mate rows and duplicate game IDs fail closed. Retrying collection must not add another experimental observation.

The result includes planned/attempted/completed/invalid/ambiguous counts; W/D/L and W+0.5D; own/opponent scores and margins; paired deltas; both per-opponent and per-seat tables; complete failure counts. Runtime failure is retained as the official loss when that is the official result. Unresolved identity invalidates the affected comparison rather than being scored as a fabricated draw. If deployment safety fails, there is no promotion regardless of a clean-game sensitivity result.

| Separate ladder block | 4 mature rollouts per arm × 2 arms × nominal 160 games | 1,280 nominal | Sole account controller; exact identity, full archive, interleaved schedule, no automatic extension |

A/A compares repeated identical policies on the same block. If a real opponent is stochastic, the strict deterministic-pair contract may fail without a mechanics defect. Stop that contract; do not quietly drop the opponent or pretend seeds fix its behavior. A separately frozen randomized/repeated design can measure noisy opponents, but requires a revised budget before new results are viewed.

For confirmation, propose paired match points as the primary outcome, margin as a diagnostic, and independent deployment validity as a prerequisite. The precise effect threshold and sample size must be chosen from a development variance estimate before opening; an old margin threshold cannot be reused as a win-probability power calculation.

## 5. Resolution: do not sell margin precision as match-point precision

The existing seal was sized using local score variability: 1.96 × 40.203456 × sqrt(2/512) = about 4.925 score points. That is not a measured official-game interval, not a power guarantee, and not a match-point percentage.

For paired match-point differences d in [-1,1], a deliberately conservative normal planning bound uses SD(d) ≤ 1. At 512 independent blocks it gives a half-width of about 0.0866, or 8.66 percentage points. Actual pairing may reduce variance substantially; it must be measured. Under that worst-case approximation, a five-percentage-point effect at 80% power requires about 3,140 blocks, not 512. The 512-block budget is therefore a bounded information purchase, not a guaranteed five-point detector. Near-zero empirical variance in a tiny pilot is not evidence of zero population variance; use a conservative planning floor or an exact bounded-outcome method.

For historical rating sensitivity, recent identical-file sample SD 0.8154937 gives nominal two-arm half-widths 1.130 at four rollouts per arm, 0.923 at six, and 0.493 at twenty-one. These calculations assume exchangeability/independence that the changing ladder may violate. A later poll of the same agent does not increase n. No margin-to-rating conversion is used.

The accompanying extension_audit.py recomputes the arithmetic and tests the outcome/ledger helpers on synthetic records. It does not pretend to execute any of these future experiments.

## 6. Ownership and readiness

The coordinator owns account authority, the global queue and seal custody. An implementer may supply a runner only under an explicit instrument task; a different agent must test restart after every state boundary, duplicate results, changed hashes, partial pairs, platform loss, non-BMP source text and an ambiguous POST. All of that can be tested with fake responses before any official game is authorized.

The current task produces this contract; it does not write a collector into production, alter the old gate, release the platform freeze, or open a test set. PLAN-v2 makes execution-layer readiness a real prerequisite rather than assuming that documentation already implements it.
