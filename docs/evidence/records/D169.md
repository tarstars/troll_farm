# D169 — Resident-native option envelope authorizes a selection programme

**Status:** `authorized`  
**Review state:** `proposed`  
**Decision date:** 2026-07-27  
**Scope:** Hindsight option-envelope value on the frozen 1,024-task panel; authorization for D170 only.

## Question

Does the resident-native option interface contain enough hindsight value to justify a closed-loop selection programme?

## Decision

Yes, the envelope contains material hindsight value, but it is a selection/timing opportunity rather than a deployable policy.

## Decisive evidence

- **full_envelope_mean**: +10.671 mean; CI [+9.420,+11.922]  
  Population: 1,024-task frozen option-envelope panel  
  Evidence: `docs/CONSTRAINTS.md` (lines 707-716) [accounting_model]
- **improvement_breadth**: 65% improved; 0 regressions  
  Population: 1,024-task frozen option-envelope panel  
  Evidence: `docs/CONSTRAINTS.md` (lines 707-716) [accounting_model]
- **deployable_subset**: +1.80 trigger-armed hindsight subset  
  Population: trigger-armed options on the same 1,024-task panel  
  Evidence: `docs/CONSTRAINTS.md` (lines 707-716) [accounting_model]

## Attempts

- D163 option primitives
- D168 return option
- D169 unified envelope

## What this does not prove

- The positive contexts are learnable from available observations.
- A per-task hindsight winner is deployable.
- D170 will pass held-out gates.

## Limitations and counterevidence

- Hindsight maximization is optimistic and trajectory-specific.
- The trigger-armed subset is still a hindsight envelope, not a policy.

- `constrains` → `D172a`
