# claude_1 delivery pipeline v2 — adopted 2026-08-05 after the banana R2 failure analysis

Trigger: three consecutive IMPLEMENTATION_INVALID verdicts (f29efd0e, 280ed777, 2f58edef).
Root-cause taxonomy: eight findings, but only two classes ever repeated — **vacuous or
scripted evidence** (r1, r2, r3) and **model divergence** (r2, r3). The orchestrator's
verification re-ran the implementing agent's instruments, which verifies the gate ladder but
not its coverage; every repeated failure was invisible to the instruments by construction.

## Change 1 — adversarial pre-review (new mandatory phase between GREEN and handoff)

A dedicated subagent, distinct from the implementer, whose only brief is to attack the
evidence the way the integrator does. Its checklist is the failure ledger (below), plus:

1. **Provenance of every critical trace**: candidate-driven closed-loop, or scripted?
   Scripted evidence on the critical path is an automatic block.
2. **Red-for-the-right-reason**: for every red/green pair, READ the failure output on the
   old bytes and confirm the failure mechanism matches the documented defect — exit codes
   are not enough (r3's R-3 shipped failing for a side reason).
3. **Single-model audit**: grep for any mechanics-derived quantity computed in more than one
   place (deadlines, ETAs, growth, costs). One named oracle per quantity; code mirrors it,
   tests import it (the CONVERSION_RACE_ORACLE rule, generalized).
4. **Claims-coverage table**: for each invariant the handoff touches, name the specific test
   that would fail if the invariant were violated. Any invariant without a falsifying test
   is flagged as UNGUARDED in the handoff — visible, not hidden.
5. **Instrument-expressiveness question**: what behaviour class can the current referee/
   fixtures NOT express? (r1's static opponents made capture untestable; nobody had asked.)

Cost ~50–80K tokens per cycle; a rejected round costs ~300K plus a day of integrator
round-trip. Break-even at one caught finding per four cycles; rounds 2–3 suggest the real
rate is higher.

## Change 2 — the failure ledger is a standing input

`claude_1/banana-restoration-r2/` reviews r1–r3 define named failure classes. Every future
pre-review reads the ledger; every new integrator finding adds a class. Classes never
retire.

## Change 3 — handoffs declare evidence types

The handoff's gate table gains a column: evidence type ∈ {candidate-driven closed-loop,
constructed fixture, static assert, scripted-control (non-critical only)}. The integrator
sees at a glance what kind of proof backs each claim.

## What does NOT change

Red-first with committed failing evidence; one-oracle imports; my manual trace-read against
the invariant list; v2 transport publication; the integrator as final reviewer. These caught
or fixed real defects every time they were applied — the changes above exist to apply their
logic earlier and systematically.
