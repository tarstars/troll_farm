## 1. What v3 adds, and what it does not touch

v2 recorded the target of the candidate that **won** selection. A troll whose real want *lost* — on
score, or to pair incompatibility — recorded `NONE`, identically to a troll that had nothing to
want. v3 adds, per live own unit per turn, **the unit-local best candidate taken from the candidate
map before joint pairing consumes it**.

```
turn 1 :  MSG yamo-waypoint-rust NARRATE v3 t=1 u0=TREE(3,10)/TREE(3,10)
turn t :  MSG NARRATE v3 t=137 u0=NONE/TREE(3,10) u2=SHACK/SHACK u4=NONE/NONE u5=NONE/ABSENT
```

```
payload   := "NARRATE" SP "v3" SP "t=" turn { SP unit }
unit      := "u" id "=" chosen "/" available
chosen    := target
available := "ABSENT" | target
target    := "NONE" | "SHACK" | "BANK(" x "," y ")" | "CELL(" x "," y ")" | "TREE(" x "," y ")"
```

- **v2's field is unchanged in name, position and meaning.** `chosen` is byte-for-byte what v2
  emitted; v3 appends `/available` to the same unit token. No v2 field was redefined.
- **`available` has three states and they are pairwise unspellable as one another.** `ABSENT` (no
  or empty candidate vector), `NONE` (an explicit WAIT / `Target::None` was locally best), and a
  concrete target. `ABSENT` is not a `Target` spelling, so it cannot be produced by the target
  grammar, and it is rejected outright in the `chosen` position.
- **The version token is `v3`.** A decoder that does not recognise the version refuses the game
  rather than guessing — proven in both directions: the v3 decoder refuses `v2`, `v4` and a missing
  token, and the **live v2 decoder refuses all three v3 states** rather than mis-reading them.
- **Capture point.** `Self::narrate_available(&by_id)` runs after every candidate-list edit
  (`force_unique_door_clear` included) and immediately before `select_recording` takes ownership of
  the map — the exact map selection is about to consume.
- **Production tie semantics by construction.** `available` is computed with the *same expression*
  the `ids.len()==1` branch of `select_recording` uses — `max_by` over `score.total_cmp` — which on
  a tie keeps the last maximum in candidate order. It is not a re-implementation.
- **The selection path is not touched.** `select_recording` keeps its v2 signature and body; the
  new function is a read over a borrowed map and returns before selection runs.

**Measured longest payload: 111 characters** over 12,981 unit-rows, against the 2,000 measured safe.

## 5. What this gate cannot prove

Unchanged from v2, restated rather than footnoted: **this harness does not react to the command
stream's length, ordering or content.** The instrument emits a `MSG` token on every turn where the
base emits one on turn 1 only. If the live referee reacts to that, G-P passes and the ladder
position is still not swap R-1's. That is the platform condition; it is not mine to run and a green
result here does not discharge it.

Also not proven here, and not claimed: that `available` reconstructs *why* a candidate lost. The
wire records what the unit's best was and what it got. Attributing a given discarded want to pair
incompatibility rather than to score loss is **not** readable from the payload alone; the two forks
above show the census is sensitive to each mechanism, which is a different and weaker statement.
