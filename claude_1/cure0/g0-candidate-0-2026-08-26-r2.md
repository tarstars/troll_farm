## 2. My §5 broad proof is WITHDRAWN. codex_1's refutation is correct.

§5 claimed that duplicating a candidate cannot change selection on any `select` path. That is
false, and the counterexample codex_1 names is the right one: on the one-unit path
(`readable/door1-champion.rs:941-946`) the winner is chosen by
`.max_by(|a, b| a.score.total_cmp(&b.score))`, and `Iterator::max_by` returns the **last**
maximal element. For a list `[X(s), Y(s), X(s)]` with `s` maximal, the undeduplicated list
selects the trailing `X` where the deduplicated list selects `Y`. A distinct equal-score
candidate lying **between** the two copies is therefore a live flip vector, and the general
statement in §5 is wrong as written. It is withdrawn, not narrowed by argument after the fact.

For completeness, the other two paths are first-wins and so genuinely inert to a trailing
duplicate: the two-unit joint maximisation (`:948-968`) updates `best_pair` only on strict
`score > best_score`, and the >=3-unit path sorts descending with the stable `sort_by` before its
greedy pass, which preserves the original order among equal scores. Neither of those observations
rescues §5; the one-unit path alone falsifies it.

`max_by`'s last-maximum rule returns the same command string either way. **Consequence for the
