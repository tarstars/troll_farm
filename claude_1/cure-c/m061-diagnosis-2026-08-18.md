# m061 seat 0 — the one tail-independent de-novo P4, diagnosed

The other real regression, m082 seat 1, is tail-caused and vanishes under the endgame tail.
**m061 seat 0 survives both tails**, so it is the one that could plausibly have been an assembly
defect in how I built the chain. It is not.

## The measurement

| | score | violations |
|---|---:|---|
| floor (resident vs itself) | 48 | D-1, P2 |
| C as specified (WAIT tail) | **75** | D-1, D-4, P2, **P4 turns 39–99** |
| variant (endgame tail) | **75** | D-1, D-4, P2, **P4 turns 39–99** |

**C and the variant are identical on this game** — same score, same violation set, same stall
window. Since the variant's only difference is that it falls back to `endgame_candidates` whenever
the chain yields nothing but `WAIT`, the two can only agree here if the resident's own endgame path
produces the same `WAIT` in that state. **No choice of tail changes this stall.**

## What actually happens

- The two bots first differ at **turn 24** (`MOVE 2 2 2` vs `WAIT`).
- Over turns 1–38 the candidate is productive: 41 MOVE, 18 CHOP, 4 DROP, 1 HARVEST.
- Over the stall window 39–99 it emits **`WAIT;WAIT` on all 61 turns**, while the parent — in its
  own, different world — emits 40 CHOP, 6 MOVE, 3 DROP, 2 PICK, 2 PLANT.
- Final score **75 against the floor's 48**.

## The reading, and the one I discarded

My first explanation was that **the chain drops the endgame planner's regeneration `PICK`**, which
the parent is visibly using in-window (2 PICK, 2 PLANT). It is a tidy story and it is **wrong**:
the endgame-tail variant *does* fall back to that planner and stalls identically. The parent's
PICKs happen in a world the candidate never reaches.

What the evidence supports is narrower: **the candidate plays differently from turn 24, reaches a
different and higher-scoring position, and then starves there** — in a state where the resident's
own generators would also have offered nothing. This is not the chain misbehaving; it is the same
starvation the resident is subject to, occurring in a game state that only exists because the
candidate played better earlier.

## Consequence for the gate

There is **no implementation fix available for m061 within C's design**, because there is nothing
in C behaving incorrectly here. By the gate's letter it is a de-novo P4 and it blocks. By mechanism
it is a trajectory consequence of a stronger game.

I record both readings and choose neither. The ruling on whether a de-novo stall reached by
outplaying the resident counts against the gate is the owner's; my job was to establish that it is
not a defect I can repair, and that is now established rather than assumed.
