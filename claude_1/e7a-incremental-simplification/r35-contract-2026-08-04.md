# Round-35 contract — delete the duplicate `carrying_any` helper (immutable)

Written before candidate generation. **Newly discovered block** from the post-round-33 scan:
a duplicate-implementation class the programme had not examined. `MoisanBot::carrying_any`
and `MoisanBot::carry_total` reimplement `Unit::total_carried()`, which already exists on the
type and is used at fifteen other sites.

- Parent: `claude_1/e7a-incremental-simplification/candidate-r34-delete-unread-scores-field.rs`,
  SHA-256 `34efd0aed85f4749aa001881f7afefdd0ac888b2d6a8cfbe0af1fd999dd5236f`
  (round 34: all four gates exact).
- Named block: `fn carrying_any(unit:&Unit)->bool{Self::carry_total(unit)>0}` and its single
  call site.

## Invariant

1. `carrying_any` occurs exactly twice: its definition and one call,
   `if Self::carrying_any(unit)||unit.free_capacity()<=0{` in `early_candidates`
   (machine-verified).
2. Body equivalence, by substitution: `carrying_any(unit)` = `carry_total(unit)>0` =
   `unit.carry.iter().sum::<i32>()>0`, and `Unit::total_carried(&self)` is defined as
   `self.carry.iter().sum()` — the same expression over the same field.

## Replacement (exact)

- delete the `carrying_any` definition;
- `if Self::carrying_any(unit)||unit.free_capacity()<=0{` →
  `if unit.total_carried()>0||unit.free_capacity()<=0{`.

## Supported-state argument

The replacement expression is textually the same computation on the same receiver; both are
pure and total, and the surrounding short-circuit order is unchanged. This is deletion of a
duplicate implementation, not a rewrite of policy: the surviving method is the one the rest
of the program already uses.

## Rejection condition

Reject if either anchor count differs; if `carrying_any` survives; if the candidate is not
strictly smaller; or if any of the four gates fails.
