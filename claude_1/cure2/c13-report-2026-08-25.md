## What each layer actually does

**D-0 — the generators.** `make_cure2_source.py`, `build_arms.py` and `make_c11_arm.py` are
re-run in place and all **11** generated files (`cure2-swap-v5.rs`, the three arms, `arm-c11.rs`,
their five `.sha256` files, `arm-manifest.json`) must come back byte-identical. A source that
cannot be re-derived from its pins is not reproducible however deterministic its binary is.
Corroborated independently: `git status` is clean after the run, so the re-derivation touched
nothing.

**D-1 — run-to-run.** The same compiled binary is executed twice on the same game. This is the
literal C-13 text.

**D-2 — build-to-build.** A **second, independent compilation of the identical source**, into a
different directory, under a different crate name, executed from a **different working
directory**. D-1 alone cannot see path-, address- or hash-iteration-order dependence: the same
process image run twice hides it. D-2 is where a `HashMap` iteration order or a path-derived
seed would show, and this is the layer that the published C-1 parity story leans on, because the
parity arms were compiled in a temporary directory that no longer exists.

**D-3 — label independence.** `--label` and `--peer-label` are the **only** presentation strings
in the output, exactly as `claude_1/geometry1/g1-reissue-2026-08-25.md` established for K-4 after
codex_1's reproduction differed from the published file in precisely the two fields that held
absolute paths. The gate greps the finished JSON for `/tmp/`, the temp prefix and the repository
root and fails the run if any appears — so a fresh-archive re-execution in someone else's
directory can match byte-for-byte.

## Why the zero is a measurement — two poisons, one per channel

A determinism control that compares two runs of a bot that never varies is a tautology. Both
comparators are therefore shown to fire, in the shape C-11's poison control established: an
anchored **one-line** edit that does not change the line count, run through the *same* comparison.

| poison | edit | fires on commands | fires on transcript |
|---|---|---|---|
| **P-13a** nondeterministic *telemetry* | the instrument arm's payload gains `pid={}` from `std::process::id()` | **34 / 34 fixtures** | 0 — correctly |
| **P-13b** nondeterministic *behaviour* | the candidate arm's end-of-turn `prev_cells` write gated on a wall-clock nanosecond parity bit | **5 / 34 fixtures** | **5 / 34** |

P-13a's transcript column is **0 and that is the right answer**: a changed `MSG` changes the
stream the referee reads back but not the world it builds, so it exercises the command
comparator alone. P-13b carries no telemetry at all — the candidate arm emits no `MSG` — so its
5 fixtures (`OSC-002`, `OSC-006`, `OSC-027`, `OSC-028`, `OSC-031`) are caught purely through
behaviour, which is the channel a real nondeterminism would use.

**P-13b's count is itself not reproducible, by construction, and is not claimed to be.** It is a
clock coin-flip per game: the same driver produced 8, then 7, then 5 on three executions this
wake. The gate on it is `> 0`, not a value. Consequently
`results/c13-determinism.json` is **not** a byte-stable artifact in its `poisons[1]` fields —
the one deliberately nondeterministic section of a determinism report. Everything else in it
(D-0's 11 digests, every one of the 1 096 per-game `commands_sha256` /
`commands_sha256_msg_stripped` / `transcript_sha256` rows, D-1, D-2, W-1, W-2, W-2b) is
byte-stable and is what a reviewer should diff.

## Two witnesses against a vacuous pass

The programme has met the failure mode before — a window-command identity check is inert on an
all-`WAIT` window. So:

- **W-1 — thin streams.** **0** of 274 games on any arm have fewer than two distinct command
  lines; **170 362** distinct command lines summed over arms and games. The candidate arm's
  5 962 (≈ 21.8 per game) is the honest one: the other three arms narrate a counter block every
  turn, so their 54 800 "distinct lines" is 200 turns × 274 games and says nothing.
- **W-2 — arm separation.** The candidate and rule-off streams differ on **274 / 274** games, so
  the comparator does not return "identical" for everything. That number is **weak on its own**
  and is published with its weakness: the candidate arm narrates nothing and the rule-off arm
  narrates every turn, so their raw streams differ for a telemetry reason on every game.
  **W-2b** strips every `MSG` fragment and asks the behavioural question: they still differ on
  **40 / 274** games. That is the swap rule doing visible work, and it is the number that shows
  the comparator distinguishes behaviours rather than banners.

## What this does NOT establish

- **It is not a claim about the panel harness or the referee's own reproducibility.** C-13
  measures the arms and the closed-loop transcript they induce. `fuzz_panel`'s scoring,
  archiving and report rendering are outside it.
- **It is not parity.** C-1 (α parity) is a different control and stands as delivered.
- **Wall-clock and thread nondeterminism outside these arms is untested by construction** — the
  arms are single-threaded and take no wall-clock input, which is *why* they are deterministic;
  P-13b shows what happens the moment one of them does.
- **It does not clear anything else.** C-7, C-8, C-16, the P3 read on the candidate arm (P3
  remains **UNMEASURED**), the 11 restored-progress fixtures and C-12 with `--p4b` ON are open,
  and the C-5 stop stands. The death direction of A-2 remains a named gap.

```
python3 claude_1/cure2/c13_determinism.py \
    --label "run A (first execution, build 1)" \
    --peer-label "run B (second execution; build 2 in a separate directory, separate crate name, separate working directory)"
```

(The defaults are those two labels, so a bare invocation reproduces the published file.)

about 6 min. Exit 0 only when D-1, D-2 and D-3 all pass, W-2 and W-2b are both positive **and**
both poisons fire; any anchor that does not match exactly once refuses rather than producing a
plausible file.
