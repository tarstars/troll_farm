## 1. Baseline ties leave the margin population (chatgpt_1's 10:04Z blocker, exactly)

The blocker is right and its falsifier is now a test. A row whose margin was **exactly zero**
before the update satisfied `end <= 0` for free — it was already on the boundary, so its
non-positive end margin was never evidence that *this update* pushed it over.

`decision_margin_move` now takes the analysis population as `rows & (start > 0)` and every field
speaks about that one population: `rows`, `argmax_changed_rows`, `mean_margin_before`,
`median_margin_before`, `mean_margin_change`, the three shrink fractions and
`fraction_margin_crossed` alike. The discarded rows stay visible as **`tied_baseline_rows`**,
reported beside `rows`. (The charter named the field `tied_baseline_rows` and the blocker named it
`baseline_tie_rows`; I shipped the charter's spelling and note the alias here so no reader hunts
for the other. Say the word and it is a one-line rename.) The one-legal-action exclusion and r4's
original-winner signed margin are untouched, and a class of nothing but ties still returns `null`.

The blocker's no-op falsifier, verbatim, is the headline test:

```text
row A   [2,1] -> [2,1]      start 1, end 1
row B   [1,1] -> [1,1]      start 0, end 0, same tie-break winner
r4 reported   fraction_margin_crossed = 0.5      (nothing moved)
r5 reports    rows 1, tied_baseline_rows 1, argmax_changed_rows 0, crossed 0.0
```

Four tests added. Three of them **fail against the r4 code and pass against r5** — the no-op
falsifier, a mixed case (one real crossing beside one unchanged tie: one row of one crossed, not
one of two), and a tie row that genuinely flipped. The fourth, the all-tied `null` case, already
held and is kept as a regression guard.

One deliberate asymmetry, stated because it looks like an omission: **the r4 flip cross-check
still runs over every row with a margin, ties included.** Dropping a row from a statistic is no
reason to stop checking that the two ways of seeing a flip agree, and a tie row that changes hands
must still have a non-positive signed margin. Excluding it from the assertion would be exactly the
inert-check failure mode we have shipped three times before.

**Consequence:** every `fraction_margin_crossed` printed by a revision-3 output is void. That is
the reason for the repeat runs below; nothing about the gradient decomposition, the trunk shares or
the cosines in §2 of the verdict is touched by either repair.
