## The finding you should rule on before I build B3/B4

The plan describes the object layout as *append-only by construction*, resting on the service
account having no delete right. Measured on my own probe key:

| Operation | Result |
|---|---|
| `DELETE` | refused, 403 `AccessDenied` — as designed |
| plain `PUT` to the same key | **succeeded**, 200, new ETag |
| `PUT` with `If-None-Match: *` | refused, 412 `PreconditionFailed` |

**The grant stops deletion; it does not stop overwriting.** Append-only holds only as long as
no code ever reuses a key — it is a property of our discipline, not of the permissions. The
remedy is in the third row: this endpoint honours `If-None-Match: *`, so the guarantee can be
made real.

**My default unless you rule otherwise:** every collector upload goes through
`if_none_match=True`, and a `PreconditionFailed` is surfaced as a genuine error rather than
swallowed as "already there" — that is precisely the collision the `daily-YYYY-MM-DD.rerun-N`
naming exists to prevent, and I would rather it be loud.

## Implementation choice

Stdlib SigV4 signer, no runtime third-party import; boto3 is installed here but is used **only
in the tests, as an independent signing oracle**. Reason: the frozen collector beside this is
urllib-only, and collector v2 runs unattended from a timer where every extra import is
something that can break at 05:47 with nobody watching. Credentials load only from
`~/.config/troll-farm/s3-keys.json`, redact themselves in `repr`/`str`, and the loader refuses
a group- or world-readable key file rather than warning.

## Three things I got wrong first, since they are the useful part

- **A suite that could not fail.** The first version used a module-level `importorskip` for
  botocore; under plain `uvx pytest` that skipped *every* test in the file and reported green
  with 1 skipped. Now the oracle imports defensively, only the differential skips, and
  `test_oracle_is_available` **fails** so the gap cannot be mistaken for a pass. Correct
  invocation is `uvx --with boto3 pytest claude_1/collector-v2/tests -q`.
- **A differential that was structurally blind.** 18/18 passed while the signer was mutated to
  drop `~` from the unreserved set. botocore's S3 signer takes the path already encoded, so
  both sides shared my encoding. Path encoding is now pinned to RFC 3986 directly. That first
  mutant was itself **inert** — CPython's `quote` never encodes `-._~` whatever `safe` says —
  so it was replaced by one that really mis-encodes, and the two mutants that exposed real gaps
  (header whitespace collapsing, signing-key derivation) are closed and re-verified as caught.
- **A bug the offline tests missed and the live run caught.** Response headers were read
  through `dict(response.headers)`, which is case-sensitive; the endpoint returns `etag`
  lowercase, so every upload reported a null ETag. Fixed, with a regression test I verified
  fails against the pre-fix code before keeping it.
