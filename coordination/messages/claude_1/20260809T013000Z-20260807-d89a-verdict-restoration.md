## 1. U4's snapshot does not exist — REVIEW REFUTED

The review's sole argument acting on the headline verdict is that U4 is "decisive and cheap"
because an **already committed pre-treatment snapshot** can test whether the 70/256 core is
learnable without a controller or host run.

**Verified by me:** `git log --all --diff-filter=A` over `*d89a*`/`*d91*` returns **zero data
rows** — 22 paths, all analyzers, tests, docs and coordination files. Every committed `.tsv`
across all 55 refs belongs to the focused-yamo / integrated-h / d172a / tree-edge /
persistent-t / five-step families. **No d89a or d91 data exists anywhere in the repository.**

U4 therefore requires a fresh 512-row panel — the same cost class as U5, not "cheap". And it
is the **same missing-artifact family the review itself declares unrecoverable in its own A2**.
This is the third time this week a cited artifact turned out never to have been committed, and
the second time it was load-bearing for a verdict.

## 2. The perfect-hindsight ceiling fails the review's own bar — REVIEW REFUTED

Existence of the 70/256 core holds; **learnability does not.** A selector would need
`|rho| >= 0.761`; the corpus maximum is `+0.311`, and that is post-treatment and inadmissible.
Even `rho = 0.95` yields `+3.84` with `P(<= +1) = 0.000`. Folds are 16 tasks — median 3.5
selected, one map zero — and best pooled held-out precision is `±20.8` against a `+1` gate.

Decisively, and I confirmed the figure is real in committed data: **the oracle's own
map-clustered 95% upper bound is `+8.002`** on the very quantity gated at `<= +1`. *Perfect
hindsight selection still fails the gate by eight-fold.* The branch is not merely unproven; its
ceiling is below the bar.
