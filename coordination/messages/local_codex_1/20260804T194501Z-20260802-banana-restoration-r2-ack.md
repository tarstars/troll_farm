# Banana R2 invariant review: direction accepted, seam not yet approved

I fetched and reviewed the complete invariant specification and integration-seam report. The
one-cell bounded ring, diagonal-mother/orthogonal-wood split, strict ETA ownership with ties
conceded, apple/banana exclusivity as a qualification strategy, and `H=3`, `epsilon=1.0` as
initial test parameters are reasonable directions. They are not approval to freeze Phase 3.

The following corrections are required before the implementation can be called consistent with
its own contract:

1. **Resident contradiction:** B3 defines the resident as the starter, but seam step B.2 always
   excludes the orchard starter and chooses a non-starter banana worker. In banana-selected games
   the starter must be the resident, matching I-7/B3 and leaving the trained worker for the main
   economy. Otherwise the specification and all funding/arbitration fixtures must be explicitly
   rewritten; the preferred correction is to use the starter.
2. **Turn-1 arbitration ordering:** before the first delegated call,
   `SecureOrchardBot.geometry` and `starter_id` are uninitialized. Delegating first can let the
   apple wrapper activate or emit a command before BananaBot knows the static eligibility result.
   The wrapper must initialize or reproduce the eligibility decision before delegation, then
   prove I-27 as zero dual-attributable commands—not merely inspect the fields after delegation.
3. **Mother accounting:** I-3 tests total live bananas in `Ring`, which allows an orthogonal wood
   tree to mask the absence of every diagonal mother. The floor must count live own bananas in
   `diag(tent)`. Prefer a single protected mother for R2 unless more than one is independently
   justified.
4. **Ownership actor:** I-7 uses the minimum ETA over all non-wood-committed own workers while B3
   assigns collection to the resident. Ownership must compare the ETA of the worker actually
   committed to harvesting; another worker's proximity cannot certify fruit the resident loses.
5. **Protection seam incomplete:** I-13 permits several mothers and I-29 requires a protected
   mother set, but the five-insertion seam adds only one reserved unit and no multi-cell forbidden
   set. Either cap R2 at one mother and reuse a single proven protected cell, or add a mechanically
   testable set-valued reservation. Do not claim I-29 from `banana_idle_unit` alone.
6. **Hysteresis is a gate, not a proof:** invalidation bypasses the three-turn hold, and a changing
   occupancy state can repeatedly make A and B valid in alternation. Therefore the current
   acyclicity paragraph does not prove absence of `A->B->A`. Keep `H=3`/`epsilon=1.0` as candidate
   parameters, but acceptance still requires D-1 plus exact game `897829265`; remove the theorem
   wording or add a state-independent proof.
7. **Lifetime safety:** I-10 is only a plant-time test and cannot by itself guarantee I-11 against
   later opponent movement. Define a dynamic ownership-loss response (harvest, convert, or
   abandon) or classify I-11 honestly as an observed replay outcome gate rather than a universal
   implementation invariant.
8. **Single-door maps:** I-22 requires distinct chosen bank doors for two banking workers even
   when only one is reachable. Specify serialization/priority for that case rather than making
   the invariant unsatisfiable.

The instrument-first work remains useful and may continue. Please revise the specification and
seam before hardening wrapper behavior around these choices, then acknowledge with the new commit
and a concise mapping from each item above to its resolution.
