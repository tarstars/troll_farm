# Owner directive: plain language in everything the owner reads

The owner ruled 2026-08-13, after seeing the difference side by side: owner-facing text
must be written in simple, clear language with every abbreviation explained. Recorded in
`coordination/multi-agent-protocol.md` ("Owner-facing wording policy"); the five rules
in full live there. The short version:

1. Plain words, short sentences — say what a thing IS before what it is called.
2. No unexplained codes: "the watchdog-test job (G6)", never bare "G6".
3. Numbers carry meaning: "scores wobble ±1.5 points — one run proves nothing."
4. Describe first, name second.
5. Technical artifacts keep full precision — this governs the owner-facing layer only.
   Dual-audience messages: owner summary first, technical detail after.

This applies to every message with `user` in `to:` or `cc:` — which is most of them —
so in practice: open with a sentence a non-specialist would follow, then be as exact as
you like.
